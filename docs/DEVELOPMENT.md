# 开发与验证

## 结构

- `main.py`：Tkinter界面、选区和设置；作者链接仅在明确点击时打开。
- `fisher/vision.py`：归一化到336×598、局部模板及颜色几何检测。
- `fisher/controller.py`：连续帧确认、状态决策、速度估计、动作锁存及结果重试。
- `fisher/runtime.py`、`scheduling.py`：后台采样、控制命令、日志与输入协调。
- `fisher/windows.py`：窗口坐标、前台检查和空格输入。
- `fisher/config.py`：默认配置、旧配置迁移、校验及原子保存。
- `fisher/packaging.py`：公开文件清单与打包完整性检查。

新增源文件或资源后同步更新 `PUBLIC_FILES`。不要将本机配置、运行输出或整个截图目录加入发布清单。

## 识别与动作约束

结果状态为 `RESULT`，`variant=record` 表示纪录页，`variant=claim` 表示开心收下。两种样式共用关闭定时器，同一结果流程切换样式不重复计数。开心收下同时检查标题模板、按钮局部模板、按钮绿色区域和暗背景；不能仅看到绿色按钮就认定为结算。纪录页使用重量图标、蓝／紫／金黄面板和暗背景组合，不依赖鱼名或纪录标题。

`controller.commit()` 只在系统输入发送成功后调用，离线回放可显式模拟。未知画面不沿用上一帧的操作。黄条被浮标遮挡时不能接受被遮挡后的缩短边界；复位后重新确认目标。截图降频不改变快捷键轮询周期，处理变慢时不补抓积压帧。

持续模式仅忽略次数和时长上限，保留失焦、无响应和未知画面暂停。修改输入后端时，必须保留Windows完整INPUT结构、焦点与位置复查及finally释放空格。

## 本地检查

```bash
python selfcheck.py
python replay.py
python build_release.py
```

自检不发送系统按键。视觉组件测试使用局部模板构造的合成画面，以及使用说明中的实际框选示例；它们不代表覆盖所有鱼种和动画。回放入口默认分析文档示例，可用 `--input` 指定自己的图像或录像。

离线测试覆盖五阶段、两类结算、重复关闭、连续模式、采样预算、快捷键、输入释放、配置迁移和发布数据边界。离线通过不能替代Windows窗口显示、原生输入、DPI、多屏和真实模拟器命中率验证。
